Evaluation dimensions at a glance

What this level certifies

Every case at this level is scored against the same dimensions below, regardless of which case study you choose. This is a high-level view so you know what "good" looks like before you start — certifies as L3 Certified — AI-Native SDLC Architect.

Minimum 3 of 5 dimensions needed to certify. Score what your project genuinely exercised — leave the rest N/A.

Dimension 1

LLM System Design

Determinism · Reasoning models · Quantization
Make deliberate, justified calls on determinism, reasoning-model choice, and cost/quantization trade-offs — at architectural scale.
Dimension 2

Agentic AI Architecture & Patterns

Design patterns for agentic systems
Apply recognised agentic design patterns with a deliberate, defensible separation of concerns, state, and control flow.
Dimension 3

MCP Design & Implementation

Model Context Protocol
Design MCP servers/clients as reusable, secure architectural components — not a one-off integration. Interfaces and governance should be explicit.
Dimension 4

AI Governance & Security

Access control · Auditability · Compliance
Build governance and security into the architecture itself — access control, auditability, prompt-injection defence, data sovereignty — at org scale.
Dimension 5

RAG Architecture & Optimization

Hybrid search · Reranking · Pipeline evaluation
Go beyond a standard pipeline: optimise with hybrid search and reranking, and measure the retrieval-quality improvement.

01

Governed Claims RAG Platform

Healthcare / insuranceAI Governance & SecurityRAG Architecture & Optimization
What you build
A reference architecture and working proof-of-concept for a claims assistant that must satisfy a Privacy Office and a Model Risk function - redaction, entitlement-scoped retrieval, grounded answers, and a complete audit trail.
What it demands
Controls must be enforced by the running system, not described in the ADR. Every access control is tested in both directions, so a platform that blocks everything fails as surely as one that leaks.
Choose it if
You work in a regulated environment, or you want the governance dimension at full weight.
Effort
Substantial. The ADR set is the primary deliverable.

02

Threat Detection Coverage Assistant

Cybersecurity / financial servicesRAG Architecture & OptimizationAI Governance & Security
What you build
An assistant that answers “do we detect this?” against a threat technique corpus and an inventory of deployed controls, defensibly enough for Audit.
What it demands
Retrieval improvement must be measured with a baseline and a delta, reported per query type rather than as one aggregate number. Analysts ask in more than one way and a single number will hide whichever kind you are failing.
Choose it if
You want to work on retrieval architecture with real measurement, or you have a security background.
Effort
Substantial. Measure before you optimise, and read the control inventory closely.

03

Deterministic Underwriting Decision Service

Insurance / lendingLLM System DesignAgentic Architecture & Patterns
What you build
A mortgage underwriting decision service where the same application must produce the same decision every time, inside a hard cost ceiling and a broker-facing latency budget.
What it demands
Determinism must be demonstrated rather than asserted, including the recorded reasoning and not just the outcome. You will also need to justify which applications deserve an expensive model using your own measurements, and decide which fields should never reach the model at all.
Choose it if
You want the system-design dimension at depth - determinism, model routing, bounded cost.
Effort
Substantial. Reproducibility is harder than it sounds.

04

Enterprise MCP Tool Gateway

Logistics / cross-industry platformMCP Design & ImplementationAI Governance & Security
What you build
One governed MCP surface where four teams reach four internal systems - tools defined once, access granted per team, credentials never exposed to the model.
What it demands
Every access request in the inventory is reasonable on its own, and they were each reviewed that way. Your authorisation model has to hold when calls are combined, which is where these designs usually fail.
Choose it if
You are heading toward platform or architecture work, or you want MCP at design scale rather than tool scale.
Effort
Substantial. The authorisation model deserves working out on paper first.

Still deciding?

Take the case closest to work you actually do.
The industry context is synthetic but the shape of the problem is not. You will write a better submission about a domain you recognise.
Or take the one furthest from it, on purpose.
If you want the learning rather than the certificate, pick the competency you are weakest on. The dimension tags under each title tell you what each case exercises most.
Open Choice is not the shortcut.
It provides no data and no starter files, and your data decisions are scored. Take it because you have a real problem in mind, not to save time.
Every case is graded the same way.
100 points, 70 to certify, up to 20 bonus points for genuinely good practice. You will also answer a few questions about your own submission at submission time.
